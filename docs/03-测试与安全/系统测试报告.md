## 1 引言

### 1.1 测试目的

验证滑坡易发性评价 WebGIS 平台的功能完整性、异常处理能力、安全防护有效性与 GIS 空间逻辑正确性，确认系统达到《需求分析说明书》验收标准。

### 1.2 测试范围

功能测试（认证/用户管理/数据/训练/可视化/成果）、异常测试、安全测试、GIS 空间逻辑专项、性能体验、兼容性、并发承载。第一轮覆盖 V1.0 全部 8 大模块 66 条用例；第二轮覆盖 V1.1 新增功能（模型上传、三模式训练、超参数、特征重要性、用户管理）及缺陷修复验证；第三轮覆盖 V1.2 并发承载（训练闸门排队、并发点查询、GZip/缓存、WAL）；第四轮覆盖 V1.2.x Docker 双容器部署（构建、全链路冒烟、重启保留、容器内并发回归）与 26 项 API 全功能审计（含前端 14 条请求路径对账）。

### 1.4 测试指标定义

| 指标 | 说明 |
|---|---|
| AUC | ROC 曲线下面积，模型区分能力主指标 |
| high_hit_ratio | 落在高/极高易发区的灾害点占比（空间命中率，校验阈值 ≥ 0.5） |
| mean_points / mean_study | 灾害点处易发性均值 / 研究区背景均值（前者应显著大于后者） |
| roundtrip_error_m | 坐标转换往返误差（< 0.05 m 视为无偏移） |

## 6 缺陷与观察项记录

### DEF-01（提示级）：逻辑回归模型空间命中率偏低

| 项 | 内容 |
|---|---|
| 现象 | 逻辑回归训练完成（AUC 0.8133，高于随机森林），但仅 16/96 灾害点（16.7%）落入高易发区，低于空间校验阈值 50%，"风险分布合理"项未通过 |
| 影响 | 若用户选择逻辑回归，成果图的风险空间分布指示性弱于随机森林 |
| 原因分析 | 易发性与环境因子为非线性关系，线性模型 AUC 尚可但概率空间分布趋于均匀（高易发区占比仅 3.2%+0.34%） |
| 处理 | 不阻塞验收：**默认模型保持随机森林**（空间命中率 74%，空间校验全通过）；逻辑回归保留为对比选项；前端训练面板默认选中随机森林 |
| 复测 | 以随机森林为默认链路复测，全部通过 |

### DEF-02（严重→已修复）：前端超参数全链路失效

| 项 | 内容 |
|---|---|
| 现象 | 第二轮测试中，训练请求携带 params（n_estimators=5、svm_C=2.5、svm_kernel=poly 等），落盘模型回读均为默认值：RF n_estimators=100（请求 5）、SVC C=1.0（请求 2.5）——前端 5 个超参数滑杆全部静默无效 |
| 影响 | 用户调节的负样本比例/树数/正则强度/核函数均不生效，训练结果与界面设置不符（功能级缺陷） |
| 原因分析 | 传递链断了两处：① `TrainStartRequest` 未声明 `params` 字段，pydantic 静默丢弃前端提交的 params；② `train_task._train_worker` 用 `**(task.params or {})` 解包调用 `run_model_train`，键值落入 `**kwargs` 兜底参数，而 `model.py` 从命名参数 `params` 字典取值 → 永远取默认 |
| 修复 | ① `TrainStartRequest` 增加 `params: Optional[dict]`，`train_start` 显式透传 `params=req.params`；② `_train_worker` 改为 `params=task.params` 命名传参（禁止 `**` 解包） |
| 复测 | 请求 n_estimators=5 → joblib 回读 n_estimators=5 ✓；请求 svm_C=2.5/kernel=poly → SVC C=2.5/kernel=poly ✓；neg_ratio 透传链路同步修复 ✓ |
| 防复发 | 《测试用例表》新增 TC-TRAIN-12/13/14（落盘模型属性回读断言）；《AI 错误案例集》收录 EC-08 |

### DEF-03（严重→已修复）：登录态读写位置不一致，用户管理面板与退出按钮消失

| 项 | 内容 |
|---|---|
| 现象 | 登录成功后页面不显示"用户管理"面板（admin）与"退出登录"按钮，v-if 条件恒假 |
| 影响 | 管理功能与退出入口不可达（功能级缺陷，Docker 部署冒烟阶段由用户使用反馈发现） |
| 原因分析 | Login.vue 登录后把 `landslide_user` 写入 **sessionStorage**，而 Home.vue 读 **localStorage**，`userInfo` 恒为 null → `v-if="userInfo"` 与 `v-if="userInfo?.role==='admin'"` 双双不渲染；连带 logout 清理业务状态时清错了存储位置（factorFiles/taskId 等存于 localStorage，却去清 sessionStorage） |
| 修复 | 统一约定：用户/令牌走 sessionStorage（与 axios 拦截器、401 清理一致），业务状态留 localStorage（刷新恢复用）。Home.vue 改读 sessionStorage；logout 两处（sessionStorage 凭证 + localStorage 业务状态）都清 |
| 复测 | 重建前端镜像后：admin 登录显示用户管理面板与退出按钮；退出后业务状态与登录态均清空；dist 产物核验 sessionStorage 读取已生效 |
| 防复发 | 《测试用例表》新增 TC-USER-12/13（登录态读写一致、退出清理完整）；《AI 错误案例集》收录 EC-10 |

### DEF-04（严重→已修复）：批量上传把 user.id 误传为 os.makedirs 的 mode 参数

| 项 | 内容 |
|---|---|
| 现象 | POST /api/upload/batch 上传文件返回 500 TypeError |
| 影响 | 批量因子上传接口不可用（功能级缺陷，第四轮全功能审计发现） |
| 原因分析 | `os.makedirs(subdir, str(user.id), exist_ok=True)` 把 `user.id` 作为第二个位置参数传入——该位置是 `mode`（目录权限），类型不符直接抛 TypeError；且目录未按用户隔离 |
| 修复 | 改为与 upload_compat 一致的安全写法：`subdir = os.path.join(UPLOAD_DIR, str(user.id), str(uuid.uuid4()))` + `os.makedirs(subdir, exist_ok=True)`，顺带补齐批量上传的用户目录隔离 |
| 复测 | 批量上传多文件 200；文件落盘 uploads/{user_id}/{uuid}/；越权访问他目录 403 |
| 防复发 | 《测试用例表》新增 TC-DATA-21（批量上传落盘与用户隔离）；《AI 错误案例集》收录 EC-11 |

### DEF-05（提示级→已修复）：特征重要性图数值标签被画布裁切

| 项 | 内容 |
|---|---|
| 现象 | 因子特征重要性条形图最长条（如 DEM 0.28）末端数值显示不全（显示"0.2("） |
| 影响 | 数值可读性受损，图件直接截屏/引用时信息不完整 |

| 修复 | X 轴最大值改为 dataMax×1.15 留白、grid right 由 8% 改为固定 64px；同时新增"下载图片"按钮（ECharts getDataURL 导出 PNG） |
| 复测 | 各因子数值完整显示；下载 PNG 标签完整；图表渲染功能回归通过 |
| 防复发 | 《测试用例表》新增 TC-TRAIN-21（图表下载与标签完整性） |
