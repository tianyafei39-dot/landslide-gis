|---|---|

| 版本 | V1.2 |

| 适用对象 | 部署人员、演示人员、日常使用人员 |

---

## 1 使用方法

1. 按"现象"列匹配你遇到的问题；
2. 按"原因与处理"逐项排查；
3. 仍无法解决时，保留**后端控制台完整报错**与**浏览器 F12 → Network 标签的响应体**，再寻求支持。

问题按类别分组：A 启动与环境 / B 页面与地图 / C 数据上传 / D 训练与结果 / E 账号与权限 / F 删除与其他。

## 2 A 类：启动与环境

| 编号 | 现象 | 原因与处理 |
|---|---|---|
| A-01 | 浏览器提示"无法访问 127.0.0.1:5173" | 前端 dev server 未运行。双击 `start-frontend.bat`（或 `start.bat` 一键拉起两个窗口） |
| A-02 | 页面能打开但数据加载失败、接口报错 | 后端 8000 未运行。双击 `start-backend.bat`，确认窗口显示 `Uvicorn running on http://127.0.0.1:8000` |
| A-03 | 启动报 `address already in use`（端口被占用） | 已有另一实例在跑：直接访问对应地址即可；或结束旧的 python/node 进程后重启。查占用：`netstat -ano | findstr :8000` |
| A-04 | start-backend.bat 提示 `venv\Scripts\activate.bat not found` | 虚拟环境缺失。执行《环境依赖与安装说明》4.1/4.2 创建 venv 并装依赖 |
| A-05 | 启动报 `JWT_SECRET 未配置，请在 .env 中配置` | `backend\.env` 缺失或缺 JWT_SECRET。补齐 .env（见部署手册第 4 章）后重启 |
| A-06 | 报 `缺少 rasterio 依赖，请在当前 Python 环境中运行: pip install rasterio` | 依赖未装全。`.\venv\Scripts\python.exe -m pip install -r requirements.txt` |
| A-07 | 报 `ModuleNotFoundError: No module named 'xxx'` | 可能用了系统 Python 而非 venv。务必用 `.\venv\Scripts\python.exe` 启动；或补装 requirements.txt |
| A-08 | 改了后端代码不生效 | uvicorn 默认未开 reload。重启后端窗口；开发时可加 `--reload` 参数 |
| A-09 | 改了前端代码页面没变化 | 分离模式 Vite 保存即热更新；不生效则刷新浏览器。单服务模式需重新 `npm run build` |
| A-10 | npm install 失败/极慢 | 网络问题。配置国内镜像源后重试：`npm config set registry https://registry.npmmirror.com` |

## 3 B 类：页面与地图

| 编号 | 现象 | 原因与处理 |
|---|---|---|
| B-01 | 地图底图空白 | 底图瓦片来自外网（ArcGIS/OSM），需联网。检查网络；可切换"无底图"模式，风险图仍正常显示 |
| B-02 | 底图加载极慢 | 外网瓦片服务波动。等待或切换底图源；不影响业务功能 |
| B-03 | 打开页面跳到登录页并提示"请先登录" | 路由守卫生效属正常。先登录再进入工作台 |
| B-04 | 风险图与底图/边界有偏移 | 正常不应偏移（空间校验往返误差 0）。若目视偏移：硬刷新（Ctrl+F5）清缓存；仍偏移则收集该任务空间校验数据反馈 |
| B-05 | 图层开关无效 | 确认训练已完成（无结果图层时开关无对象）；刷新重试 |
| B-06 | 点击地图无弹窗 | 确认训练完成且点击的是风险图覆盖区；查看 F12 Network 是否发出 /api/result/query 且返回 200 |

## 4 C 类：数据上传

| 编号 | 现象 | 原因与处理 |
|---|---|---|
| C-01 | 提示"缺少 .prj 投影文件，无法定位" | Shapefile 须全套上传（.shp/.shx/.dbf/.prj 同名一套），缺 .prj 无法定位坐标系。重新多选全套文件上传 |
| C-02 | 提示"解析失败：…" | .shp/.dbf 等文件损坏或边车不配套（如不同名）。用 GIS 软件重新导出全套后再传 |
| C-03 | 提示"未找到 .shp 文件" | 选择文件时漏了 .shp 主文件。重新多选，确保文件组里包含 .shp |
| C-04 | 一次选了多套 shp 文件 | 一个文件组只放一套 shp（shp/shx/dbf/prj 同名）。灾害点与研究区分两次分别上传 |
| C-05 | 提示"栅格缺少 CRS 投影信息: xxx.tif" | tif 无投影定义。在 GIS 软件中定义投影（.prj/内嵌 CRS）后重新导出；推荐统一投影 EPSG:32647 或全组一致的投影 |
| C-06 | 提示"栅格未对齐：xxx (shape=..., crs=...) 与参考栅格 ... 不一致" | 各因子栅格行列数/像元大小/投影不一致。用 GIS 软件统一重采样至相同分辨率、范围与投影后重传 |
| C-07 | 提示"投影/网格不一致"（页面校验结论） | 同 C-06。以 inspect 结论中的 crs/shape 对比找差异项 |
| C-08 | 上传后列表移除了但磁盘文件还在 | 若是内置示例数据属正常（受保护仅前端移除）。用户上传文件点击 × 应同时删服务端文件，失败会有"服务端文件删除失败"提示 |
| C-09 | 提示"未接收到任何文件" | 未选文件就提交。重新选择文件再上传 |
| C-10 | 模型上传提示"仅支持 .joblib 或 .pkl 文件" | 只接受 sklearn joblib/pkl 模型。用 joblib.dump 导出后再传 |
| C-11 | 模型上传提示"文件名不合法" | 文件名含路径分隔符或以点开头。重命名为普通文件名（如 mymodel.joblib）再传 |
| C-12 | 上传的模型训练时报"上传的模型必须是分类模型，且包含 predict_proba 方法" | 传了回归模型或非 sklearn 估计器。须为分类器（RF/Logistic/SVC(probability=True) 等） |

## 5 D 类：训练与结果

| 编号 | 现象 | 原因与处理 |
|---|---|---|
| D-01 | 提示"请先上传因子栅格与灾害点样本，并确保因子网格对齐" | 训练前置校验未过。补齐因子与样本；确认 inspect 校验 aligned=true |
| D-02 | 训练失败：`没有可用正样本点，请检查灾害点是否落在研究区/因子范围内` | 灾害点全部落在研究区外或因子有效区外。核对样本与研究区/因子范围是否同一区域、同一投影 |
| D-03 | 训练失败：`未知 model_type: xxx` | model_type 仅支持 randomforest / logistic。前端下拉选择即可，勿手工改请求 |
| D-04 | 进度条长时间不动 | 大栅格训练耗时属正常（示例数据约 10 秒，更大数据更久）。若 5 分钟无变化，看后端窗口有无报错，重启后重试 |
| D-05 | 提示"训练失败：..."（其他异常） | 按提示处理；保留后端窗口完整 traceback 反馈 |
| D-06 | 训练完成但"结果图层生成失败" | 渲染阶段异常。后端窗口查 build_web_bundle 相关报错；重启后重新训练 |
| D-07 | 提示"任务正在运行，无法删除，请等待训练结束"（409） | 设计如此。等状态变为 finished/failed 再删 |
| D-08 | 提示"任务不存在或已被删除" | 任务已清理或 ID 错误。刷新任务列表重新操作 |
| D-09 | 提示"任务未完成" | 对运行中任务取结果。等 finished 后再下载/查询 |
| D-10 | 逻辑回归结果风险图分布"不合理"提示 | 已知特性（见测试报告 DEF-01）：线性模型空间命中率低。改用默认的随机森林重新训练 |
| D-11 | AUC 偏低（< 0.7） | 与数据有关：检查因子数量、样本量、研究区大小；可增加因子或检查样本质量。示例数据随机森林 AUC 约 0.79 属正常 |
| D-12 | 点查询提示"该位置超出结果栅格覆盖范围" | 点击位置在研究区外属正常。点击研究区内任意点 |
| D-13 | 点查询提示"该像元无有效易发性值" | 点在 nodata/研究区空洞。换点重试 |
| D-14 | 导出 PNG 内容不全/下载失败 | 确认训练完成后再导出；换 Chrome/Edge 重试；磁盘空间不足也会影响 |
| D-15 | 下载的 TIF 在 GIS 软件中打不开/无投影 | 正常应带 EPSG:32647 等投影。若无投影，检查训练输入因子是否本身缺投影 |
| D-16 | 调了超参数滑杆但结果没变化 | V1.1 早期缺陷（DEF-02）已修复。确认升级到修复版；自测方法：请求 n_estimators=5 后 joblib.load 回读落盘模型应为 5 棵树 |
| D-17 | 上传模型后训练报"自定义模型文件不存在" | custom_model_path 不对（应为 /api/model/upload 返回的绝对路径）。重新上传后把返回的 model_path 原样传给训练接口；此报错是刻意行为（防止静默回退成默认训练） |
| D-18 | 搭积木模式提示"不支持的算法类型" | pipeline_config.algorithm 只能是 randomforest / svm / logistic |
| D-19 | 特征重要性面板为空 | 模型无法提取 importance/coef（罕见）或训练未完成。不影响主流程，可忽略 |
| D-20 | 控制台出现 sklearn InconsistentVersionWarning | 上传的模型由其他 sklearn 版本训练（如 1.6.1 训练、1.9.1 加载）。多数情况可用；建议统一环境版本，或在目标环境重新训练导出模型 |
| D-21 | SVM/逻辑回归训练报错或指标异常 | pipeline 模式记得配 probability=True 的 SVM（后端已默认开启）；数据量过小时 SVM 拟合慢属正常 |
| D-22 | 训练一直显示"排队中（前方 N 个任务）"不动 | V1.2 并发闸门生效：同时最多跑 `TRAIN_MAX_CONCURRENT`（默认 2）个训练，其余排队。等前方任务完成自动开跑；若前方任务卡死，让其失败/删除后重试 |
| D-23 | 多人同时点训练，怕机器扛不住 / 想调大并发 | 默认闸门=2 已保护整机（超出发排队）。机器核多内存大时可改 `backend\.env` 的 `TRAIN_MAX_CONCURRENT=3`（1~4）后重启后端；单个训练的 CPU 占用会自动按"核数÷并发数"均分 |
| D-24 | 多人同时用页面卡、下载成果慢 | V1.2 起大响应自动 GZip 压缩、PNG/TIF 带 24h 浏览器缓存。仍慢则检查网络与机器负载；点查询/登录不受训练闸门影响 |

## 6 E 类：账号与权限

| 编号 | 现象 | 原因与处理 |
|---|---|---|
| E-01 | 登录提示"用户名或密码错误" | 核对账号口令；区分大小写。初始管理员见部署手册（仅首次建号生效） |
| E-02 | 登录提示"账号已禁用" | is_active=false。联系管理员启用（或删库重建） |
| E-03 | 接口返回 401"登录已过期，请重新登录" | 令牌过期（默认 8 小时）或被篡改。重新登录 |
| E-04 | 接口返回 403"无权查看该任务/删除该任务/删除他人的文件/使用他人的数据文件" | 数据隔离生效：普通用户只能操作自己的任务与文件。换用本人上传的数据或请 admin 操作 |
| E-05 | 忘记管理员口令 | 无找回机制（单机演示系统）。停服 → 删 `backend\sql_app.db` → 重启自动重建 admin（会清空全部账号与登录态） |
| E-06 | 想新增普通用户 | V1.1 起支持：① 登录页自助注册（注册即 user 角色）；② admin 在"用户管理"面板创建用户并指定角色 |
| E-07 | 操作用户管理接口返回 403 | 用户管理仅 admin 可用。换 admin 账号操作 |
| E-08 | 修改角色/删除用户提示"不能修改自己的角色/不能删除自己" | 自保机制：admin 不能删改自己（防锁死管理权限）。让另一个 admin 操作，或操作其他账号 |
| E-09 | 删掉的用户仍能登录？ | 物理删除后令牌校验会查库失败返回 401。若仍有缓存页面，重新登录即可 |

## 7 F 类：删除与其他

| 编号 | 现象 | 原因与处理 |
|---|---|---|
| F-01 | 提示"仅允许删除上传目录内的文件"（403） | 设计保护：`data/raw` 示例数据与系统文件不可通过接口删除。用户数据请从上传目录管理 |
| F-02 | 提示"无权删除他人的文件"（403） | 只能删自己目录（uploads/{user_id}/）下的文件 |
| F-03 | 删了 shp 但 .dbf/.prj 还在 | 正常应级联删除同名边车。若残留，手动删除同名 .shx/.dbf/.prj 等；或删整个批次目录 |
| F-04 | 删除任务后想恢复 | 不可恢复（TIF/PNG/GeoJSON 一并清理）。重要成果请及时导出保存 |
| F-05 | DELETE 接口传 body 不生效 | 设计如此：删除接口用**查询参数**（?target=task&task_id=...），规避 DELETE 携带 body 的兼容问题 |
| F-06 | 服务重启后历史任务不见了 | 任务表为内存态（演示系统约束）。训练产物文件仍在 result/ 目录，但失去任务索引；重要任务请及时导出 |
| F-07 | Swagger 文档打不开 | 确认后端已启动后访问 http://127.0.0.1:8000/docs（端口是否被占） |

## 8 快速诊断流程（仍无法定位时）

1. **看后端窗口**：是否有红色 traceback——最后一条异常即根因；
2. **看浏览器 F12**：Network 中红色请求的状态码与 `detail` 字段——400 参数/数据问题，401 未登录，403 越权，404 不存在，409 冲突；
3. **最小复现**：点「载入示例数据」→「启动训练」——若示例链路通过，说明环境正常，问题出在自有数据（多为投影/网格不一致，见 C-05/C-06）；
4. **收集信息反馈**：报错截图 + 后端 traceback + 数据来源说明。
