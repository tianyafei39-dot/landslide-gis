## 1 部署架构概述

| 模式 | 服务构成 | 访问地址 | 适用场景 |
|---|---|---|---|
| **主模式：前后端分离** | Vite 前端（:5173）+ FastAPI 后端（:8000） | http://127.0.0.1:5173 | 日常开发与演示（改代码热更新） |
| 备选模式：单服务 | FastAPI 后端托管前端构建产物（:8000） | http://127.0.0.1:8000 | 演示环境只开一个窗口 |

前端通过 Vite 代理把 `/api`、`/static` 转发到后端 8000 端口（配置见 `frontend/vite.config.js` 的 `server.proxy`），浏览器侧无跨域问题。

## 2 一键启动（推荐）

**双击项目根目录的 `start.bat`**，自动弹出两个控制台窗口：

| 窗口标题 | 服务 | 地址 |
|---|---|---|
| Landslide Backend :8000 | FastAPI 后端 | http://127.0.0.1:8000 |
| Landslide Frontend :5173 | Vite 前端开发服务器 | http://127.0.0.1:5173 |

浏览器打开 **http://127.0.0.1:5173** 即可使用。

> ⚠ 两个黑色窗口都是服务器进程，**都不要关闭**，关了对应服务即停止。

### 2.1 脚本说明

| 脚本 | 作用 | 内部逻辑 |
|---|---|---|
| `start.bat` | 一键拉起前后端 | 依次调起 start-backend.bat 与 start-frontend.bat（各自独立窗口） |
| `start-backend.bat` | 仅启动后端 | 激活 `backend\venv` → `python -m uvicorn main:app --host 127.0.0.1 --port 8000`；venv 缺失时报错并暂停 |
| `start-frontend.bat` | 仅启动前端 | `cd frontend` → `npm run dev`；package.json 缺失时报错并暂停 |

## 3 手动启动

### 3.1 分离模式（两个窗口）

窗口 1 —— 后端：

```powershell
cd d:\my\landslide-webgis-platform\backend
.\venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

窗口 2 —— 前端：

```powershell
cd d:\my\landslide-webgis-platform\frontend
npm run dev
```

浏览器访问 http://127.0.0.1:5173。

### 3.2 单服务备选模式（一个窗口）

```powershell
cd d:\my\landslide-webgis-platform\frontend
npm run build
cd ..\backend
.\venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

浏览器访问 **http://127.0.0.1:8000**（不再需要 5173 端口）。后端检测到 `frontend\dist` 存在时自动挂载托管（SPA 路由由 html=True 支持）。

### 3.3 启动成功的标志

| 服务 | 成功标志 |
|---|---|
| 后端 | 窗口显示 `Uvicorn running on http://127.0.0.1:8000`；首次启动打印"管理员账号 admin 初始化成功"（仅首建） |
| 前端 | 窗口显示 `Local: http://127.0.0.1:5173/` |
| 联调验证 | 浏览器打开前端地址，地图与登录页正常加载 |

## 4 环境变量（.env）配置说明

配置文件位置：**`backend\.env`**（python-dotenv 加载，仅后端读取）。改后须**重启后端**生效。

### 4.1 变量清单

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| JWT_SECRET | **是** | 无（缺失则启动报错 `JWT_SECRET 未配置，请在 .env 中配置`） | 令牌签名密钥，生产/演示环境请改为随机长字符串 |
| JWT_ALGORITHM | 否 | HS256 | JWT 签名算法，保持默认即可 |
| ACCESS_TOKEN_EXPIRE_MINUTES | 否 | 480 | 登录令牌有效期（分钟），8 小时 |
| ADMIN_USERNAME | 否 | admin | 初始管理员用户名 |
| ADMIN_PASSWORD | 否 | admin123456 | 初始管理员密码（**仅首次建号使用**，已存在不会覆盖；上线前请修改） |
| SIGN_SECRET | 否 | 同 JWT_SECRET | 预留签名密钥 |
| RESULT_URL_EXPIRE_SECONDS | 否 | — | 结果链接有效期（预留） |
| CORS_ORIGINS | 否 | http://localhost:5173 | 跨域白名单，多个用逗号分隔 |
| TRAIN_MAX_CONCURRENT | 否 | 2 | **训练并发上限**（V1.2）：同时真正在跑的训练任务数，超出的排队等待；建议 1~4，机器内存小取 1，核多可取 3~4 |
| TRAIN_N_JOBS | 否 | CPU核数÷TRAIN_MAX_CONCURRENT | 单个训练的 sklearn `n_jobs`（自动计算，无需手配）；并发训练均分 CPU 防抢核 |

### 4.2 示例

```dotenv
JWT_SECRET=请替换为随机长字符串
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=480

ADMIN_USERNAME=admin
ADMIN_PASSWORD=请改为强口令

SIGN_SECRET=请替换为随机长字符串
RESULT_URL_EXPIRE_SECONDS=3600
CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173

# 训练并发（V1.2，可选）：同时最多跑几个训练，其余排队
TRAIN_MAX_CONCURRENT=2
```

### 4.3 配置要点

1. **JWT_SECRET 必配**：缺失时后端启动直接抛 RuntimeError，属有意设计（拒绝弱密钥默认值）；
2. **管理员初始化幂等**：仅当 users 表无该用户名时插入；改 `ADMIN_PASSWORD` 对已有账号无效，需删库重建或另行改密；
3. **CORS 与端口**：分离模式经 Vite 代理同源访问，CORS 通常不触发；单服务模式同源也无跨域。仅当前端直连后端（如换端口/远程访问）才需调整白名单；
4. **训练并发调优（V1.2）**：`TRAIN_MAX_CONCURRENT` 控制同时执行的训练数（默认 2），超出任务在前端显示"排队中（前方 N 个任务）"；该闸门为**单进程内**信号量，多 uvicorn worker 部署不共享（当前为单进程部署）。改后须重启后端生效。

## 5 端口与目录约定

### 5.1 端口

| 端口 | 服务 | 占用冲突处理 |
|---|---|---|
| 8000 | FastAPI 后端 | 结束旧 python 进程，或改启动命令端口（需同步改 vite.config.js 代理目标） |
| 5173 | Vite 前端 | 结束旧 node 进程；被占用时 Vite 自动尝试 5174 等，以窗口输出为准 |

### 5.2 关键目录（勿随意移动/删除）

| 目录/文件 | 用途 |
|---|---|
| `backend\.env` | 环境配置（含密钥，勿外传） |
| `backend\venv` | Python 虚拟环境 |
| `backend\sql_app.db` | SQLite 用户数据 |
| `backend\uploads` / `models` / `result` | 上传文件 / 模型 / 训练产物 |
| `data\raw` | 内置示例数据（受保护） |
| `frontend\vite.config.js` | 前端代理配置 |

## 7 日常使用流程（验收演示路径）

1. 双击 `start.bat`，打开 http://127.0.0.1:5173；
2. 使用管理员账号登录（默认 admin / 首次配置的口令）；
3. 点击「载入示例数据」→ 因子列表与校验结论出现；
4. 点击「启动训练」→ 进度条约 10 秒走完；
5. 风险图自动叠加，右侧查看 AUC 与分级占比；
6. 单击地图任意点 → 查看等级、概率与防护建议；
7. 「导出风险图 PNG」/「下载结果 TIF」获取成果；
8. （可选）「删除结果」验证产物清理。

## 8 Docker 容器部署（V1.2 新增，方案 B：nginx 反代双容器）

> 适用：装有 Docker Desktop 的 Windows / Linux 机器。容器化后与本机 venv 方式**二选一**，数据目录共用。

### 8.1 架构与文件

```
浏览器 → frontend(nginx) :8080 ──静态页面自给
                    ├─ /api/  反代 → backend(uvicorn) :8000（compose 内网，不对外）
                    └─ /static/ 反代 → backend :8000
```

| 文件 | 作用 |
|---|---|
| `docker-compose.yml` | 双服务编排：backend + frontend，卷挂载与端口映射 |
| `docker/Dockerfile.backend` | python:3.14-slim（对齐实测 venv）+ requirements.txt（清华 pip 源）+ libexpat1（rasterio 运行时库）+ uvicorn |
| `docker/Dockerfile.frontend` | node:20-alpine 构建 dist → nginx:alpine 托管与反代 |
| `docker/nginx.conf` | SPA 回退、`/api`、`/static` 反代、`client_max_body_size 200m`（大栅格上传） |
| `.dockerignore` | 排除 venv/node_modules/data/uploads 等，镜像不带业务数据 |

### 8.2 前置条件

1. 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows 需启用 WSL2 后端），命令行 `docker --version`、`docker compose version` 均可用；
2. 项目根目录下 `backend/.env` 已配置（JWT_SECRET 等，同第 4 章）；
3. 首次部署已将存量库拷入挂载目录（升级部署时）：`cp backend/sql_app.db data/db/sql_app.db`（保账号延续；全新部署可跳过）。

### 8.3 构建与启动

```bash
# 项目根目录执行
docker compose up -d --build     # 首次构建约 5~10 分钟
```

启动后访问 **http://localhost:8080**（分离模式的 5173 / 直跑模式的 8000 由容器入口统一为 8080）。

**国内网络注意事项（实测有效）：**

1. **Docker Hub 不可直连**时，基础镜像改走 DaoCloud 镜像拉取后打本地标签，再构建：
   ```bash
   docker pull docker.m.daocloud.io/library/python:3.14-slim && docker tag docker.m.daocloud.io/library/python:3.14-slim python:3.14-slim
   docker pull docker.m.daocloud.io/library/node:20-alpine  && docker tag docker.m.daocloud.io/library/node:20-alpine node:20-alpine
   docker pull docker.m.daocloud.io/library/nginx:alpine    && docker tag docker.m.daocloud.io/library/nginx:alpine nginx:alpine
   ```
2. **pip/npm 加速已内置**在 Dockerfile 内（pip 走清华 PyPI 源、npm 走 npmmirror），无需额外配置；
3. **Python 版本必须 ≥ 3.11**：`requirements.txt` 精确锁定的 SQLAlchemy 2.1.x 等要求 Python ≥ 3.11，镜像基座为 python:3.14-slim（与实测 venv 3.14.6 一致），**不要**改回 3.10 基座；
4. **slim 镜像缺 rasterio 动态库**：Dockerfile 已装 `libexpat1`（报 `libexpat.so.1: cannot open shared object file` 即此原因）。

### 8.4 数据卷（与本机直跑共用宿主目录）

| 卷 | 容器内路径 | 说明 |
|---|---|---|
| `./data/raw`（只读） | `/app/data/raw` | 内置示例数据（DEMO_DATA_DIR） |
| `./backend/uploads` | `/app/backend/uploads` | 用户上传数据/自定义模型 |
| `./backend/result` | `/app/backend/result` | 结果 TIF/PNG/GeoJSON（/static） |
| `./backend/models` | `/app/backend/models` | 落盘模型 joblib |
| `./data/db` | `/app/data/db` | SQLite（`DB_PATH` 环境变量指向 `sql_app.db`，WAL 伴生文件同目录） |

> 镜像本身**不含**任何业务数据（.dockerignore 排除）；重建镜像不清数据，`docker compose down` 也不删卷挂载目录。

### 8.5 常用运维命令

| 操作 | 命令 |
|---|---|
| 查看状态 | `docker compose ps` |
| 看后端日志 | `docker compose logs -f backend` |
| 重启服务 | `docker compose restart` |
| 改代码后重建 | `docker compose up -d --build` |
| 停止并移除容器 | `docker compose down`（数据保留） |
| 改 .env 后生效 | `docker compose up -d`（重建容器） |

### 8.6 注意事项

1. **训练并发**：容器为单进程 uvicorn，训练闸门 `TRAIN_MAX_CONCURRENT`（默认 2）在容器内照常生效；backend 限制内存 4GB（compose `mem_limit`），更大并发需求先调该值；
2. **端口冲突**：宿主机 8080 被占用时改 `docker-compose.yml` 的 `ports` 映射（如 `"8081:80"`）；
3. **前端请求地址**：前端已改为同源相对路径（`/api/...`），由 nginx 反代——不要再改回 `127.0.0.1:8000` 硬编码；
4. **与本机直跑互斥**：同一数据目录不要让 venv 直跑服务和容器**同时**写（SQLite 并发写跨进程不保证）。
